# Тепловая карта контекста

Тепловая карта контекста — исследовательская диагностика агентской сессии.
Она показывает, какие фрагменты prompt-пакета занимают место, повторяются,
устаревают, несут недоверенный текст или исчезают перед важным действием.

Первый вариант работает пассивно: harness не меняет политику контекста, а только
пишет более подробную телеметрию в JSONL-трассу. Отдельный CLI-анализатор читает
trace и строит машинные отчеты, Markdown и статический HTML.

## Цель метода

Обычная длина контекста не объясняет качество агентской траектории. Длинный
prompt может быть полезным, если в нем много свежих доказательств. Короткий
prompt может быть опасным, если из него исчез результат теста, пользовательское
ограничение или актуальное чтение файла.

Тепловая карта разделяет два сигнала:

- красный нагрев — в контексте есть дорогие, шумные, устаревшие или рискованные
  фрагменты;
- холодные дыры — перед действием не хватает доказательства, которое должно
  быть в prompt.

## Граница MVP

MVP анализирует уже записанные сессии. Он не сжимает историю, не переставляет
фрагменты и не блокирует инструменты. Это важно для учебного harness: сначала
нужно увидеть устойчивые паттерны на реальных trace, а уже потом включать
политики управления контекстом.

В MVP входят:

- расширенный `context_report.context_packet` без полного текста prompt;
- нормализация trace в `SessionEvent`;
- восстановление `ContextPacket` для каждого обращения к модели;
- расчет осей heat и cold gaps;
- `JSONL`, `CSV`, Markdown и самодостаточный `heatmap.html`.

## Формат телеметрии

`ContextManager.report()` добавляет диагностический `context_packet`. Это индекс
prompt-сборки: порядок фрагментов, тип источника, примерная позиция, оценка
токенов, причина включения, hash содержимого и confidence.

Текст prompt, длинные выводы инструментов и секреты туда не попадают. Анализатор
использует hash и метаданные, чтобы видеть повторы и давление окна, не раздувая
trace.

Старые trace без `context_packet` поддерживаются в legacy-режиме. Анализатор
восстанавливает пакет по доступному `context_report`, но снижает
`reconstruction_confidence` и пишет warning
`legacy_trace_without_context_packet`.

## CLI-анализатор

Пакет `context_heatmap/` живет рядом с harness, но не является частью runtime
цикла агента.

Основные команды:

```bash
context-heatmap validate --input .madharness-mini/traces/<id>.jsonl
context-heatmap normalize --input .madharness-mini/traces/<id>.jsonl --out reports/normalized
context-heatmap analyze --events reports/normalized/events.jsonl --out reports/session
context-heatmap render --report reports/session/session_report.json --out reports/session/heatmap.html
context-heatmap analyze-batch --input .madharness-mini/traces --out reports/corpus
```

Выходы одной сессии:

- `events.jsonl`;
- `fragments.jsonl`;
- `packets.jsonl`;
- `fragment_heat.jsonl`;
- `turn_heat.jsonl`;
- `findings.jsonl`;
- `session_report.json`;
- `report.md`;
- `heatmap.html`;
- `warnings.jsonl`.

## Визуализация

Статический HTML показывает обращения к модели по горизонтали и фрагменты по
вертикали. Цвет ячейки — итоговый heat. Холодные дыры показываются отдельным
синим/серым сигналом в findings, чтобы не смешивать перегрев с отсутствующим
доказательством.

HTML хранит данные внутри страницы, поэтому отчет можно открыть без сервера.

## Роадмап

### Phase 0. Телеметрия prompt-сборки

Расширить `context_report` диагностическим `context_packet`. Проверить, что
позиции монотонны, схемы tools считаются отдельно, а полный prompt не пишется в
trace.

### Phase 1. Нормализатор trace

Сделать загрузчик `madharness-mini` JSONL и нормализовать события в
`SessionEvent`. Для legacy trace без `context_packet` включить низкую
уверенность и warning.

### Phase 2. Scoring

Посчитать оси heat: давление окна, низкая полезность, устаревание,
дублирование, позиционный риск, taint, риск сжатия. Отдельно искать cold gaps,
например правку файла без актуального чтения.

### Phase 3. Статический HTML

Собрать `heatmap.html`, Markdown-отчет и машинные JSONL/CSV-выходы. HTML должен
показывать причины нагрева и не печатать секреты.

### Phase 4. Корпус сессий

Прогнать 20-50 реальных trace, посмотреть распределение heat, частые cold gaps,
сырой tool output и legacy-слабые места. После этого откалибровать пороги
yellow/orange/red.

### Phase 5. Экспериментальные политики

Только после пассивной проверки пробовать политики: замена сырого вывода на
summary, перемещение критичных доказательств, перечитывание файла перед patch,
изоляция недоверенного текста и сжатие старой истории по сигналам heat.
