# Возможности полной версии

`madharness-mini` помогает модели работать с локальным репозиторием через
управляемый харнесс: контекст, инструменты, безопасность, трассы и расширения
остаются явно описанными в коде.

## Команды CLI

| Команда | Что делает |
| --- | --- |
| `madharness-mini init` | Создаёт или обновляет `.madharness-mini/config.json`. |
| `madharness-mini ask "..."` | Отправляет один запрос модели без инструментов. |
| `madharness-mini run "..."` | Запускает агентский цикл с инструментами, контекстом, навыками, MCP, субагентами и hooks. |
| `madharness-mini trace <id>` | Показывает краткую сводку JSONL-трассы. |
| `madharness-mini skills list/show/validate` | Диагностирует проектные Agent Skills. |
| `madharness-mini subagents list/show/validate` | Диагностирует встроенных и проектных субагентов. |

## Инструменты `run`

| Инструмент | Что делает |
| --- | --- |
| `list_files` | Показывает файлы внутри workspace с лимитом результатов. |
| `read_file` | Читает UTF-8 фрагмент файла по строкам. |
| `read_image` | При включённом vision input прикрепляет локальное изображение к следующему обращению к модели. |
| `search_code` | Ищет буквальную подстроку в файлах проекта. |
| `apply_patch` | Применяет точечные файловые правки. |
| `write_file` | Полностью перезаписывает UTF-8 файл. |
| `run_shell` | Запускает одну разрешённую команду в workspace или безопасном `cwd`. По умолчанию исполняется через `/bin/sh -c`, поэтому операторы `&& ; \|\|` и конструкции `\|`, `2>&1`, `>/dev/null` работают. Разрушительные команды (`rm -rf`, `sudo`, `curl`, ...) и редирект в файлы блокируются политикой в любом режиме. |
| `run_shell_background` | Запускает и управляет фоновым процессом (`action: start \| status \| stop`) — HTTP/dev-сервер, watcher и т.п. Процессы хранятся в пуле provider'а и автоматически гаснут при завершении сессии. Та же политика, что у `run_shell`; лимит `max_background_processes`. |
| `activate_skill` | Подключает проектный навык в закреплённый контекст. |
| `delegate_task` | Делегирует задачу Markdown-субагенту. |
| `ask_user` | Доступен только разрешённым субагентам; завершает запуск вопросом пользователю. |
| `mcp__...` | Инструменты, полученные от явно включённых stdio MCP-серверов. |

## Настройки

Основной файл:

```text
.madharness-mini/config.json
```

Отдельные файлы расширений:

```text
.madharness-mini/mcp.json
.madharness-mini/hooks.json
.madharness-mini/subagents/<name>.md
.madharness_mini/skills/<name>/SKILL.md
.agents/skills/<name>/SKILL.md
```

Важные поля `config.json`: `model`, `base_url`, `api_key`, `temperature`,
`max_turns`, `context_max_tokens`, `context_keep_recent_turns`,
`context_summarize_after_turns`, `context_summary_trigger_tokens`,
`context_reserve_tokens`, `context_contract_protection_turns`,
`context_contract_protection_writes`, `context_workspace_map`,
`context_workspace_map_depth`, `context_workspace_map_max_entries`,
`context_shell_full_output`, `orchestration_mode`, `subagent_max_turns`,
`subagent_context_max_tokens`, `workspace_root`, `protected_paths`,
`allow_shell`, `allow_shell_interpreter`, `max_background_processes`,
`supports_image_input`, `max_image_bytes`, `image_detail`.

## Управление контекстом

Слой контекста удерживает окно модели в пределах бюджета и защищает актуальное
состояние файлов от потери. Поведение настраивается следующими knobs:

| Knob | По умолчанию | Назначение |
| --- | --- | --- |
| `context_summarize_after_turns` | `3` | Возрастная компактизация: ходы старше указанного числа сворачиваются (текст рассуждений, наблюдения tool и тяжёлые аргументы `write_file`/`apply_patch`), чтобы окно реже доходило до предела. |
| `context_summary_trigger_tokens` | `45000` (≈75% бюджета) | Второй эшелон: токеновый порог LLM-суммаризации; при превышении старые незащищённые ходы сворачиваются в накопительный фрагмент. `0` отключает LLM-вызовы. |
| `context_reserve_tokens` | `0` (выкл) | Headroom для проактивного усечения: дроп истории срабатывает при оценке свыше `context_max_tokens − reserve`, а не при достижении самого предела. Между порогом дропа и жёстким потолком остаётся запас под рост следующих ходов. `0` сохраняет прежнее поведение (дроп только у самого `max_tokens`). |
| `context_contract_protection_turns` | `12` | Fan-out защита: окно ходов после чтения контракта, в котором ищем правки других путей. |
| `context_contract_protection_writes` | `3` | Минимум различных путей, правленных в окне, чтобы удержать контрактное чтение в окне. |
| `context_workspace_map` | `true` | Подмешивать карту проекта (дерево каталогов) в начале сессии. |
| `context_workspace_map_depth` | `3` | Максимальная глубина дерева в карте проекта. |
| `context_workspace_map_max_entries` | `200` | Максимальное число записей в карте проекта. |
| `context_shell_full_output` | `true` | При обрезке вывода `run_shell` сохранять полный `stdout`/`stderr` во временный файл `.madharness-mini/tool_outputs/`, а модели отдавать хвост (там обычно ошибки/итог) и путь для перечитывания через `read_file`. `false` возвращает прежнее поведение (голова через `clipped`, полный вывод теряется). |

Ключевые механизмы:

- **Защита актуального чтения.** Единый предикат не даёт свернуть или выбросить
  чтение файла, который позже был изменён: одно правило работает во всех путях
  эвикции (возрастная компактизация, дедуп `read_file`, дроп по бюджету), чтобы
  модель не правила файлы «вслепую».
- **Скелет свёрнутой истории.** Когда старые ходы выбрасываются по бюджету,
  остаётся детерминированный фрагмент-скелет: для каждого свёрнутого хода — его
  тип и список вызванных инструментов с путями и статусом `ok/fail`. Модель видит,
  что именно было свёрнуто.
- **Усиленное напоминание о грязных файлах.** Напоминание различает две
  категории: файлы, которые были изменены, но не перечитаны после правки, и
  файлы, которые записаны, но ни разу не прочитаны.
- **Дайджест старых правок.** Возрастная компактизация сворачивает аргументы
  `write_file`/`apply_patch` старых ходов в указатель (путь и размер payload),
  роняя само тело файла: код уже применён к диску и переотправляется каждый ход,
  доминируя в стоимости assistant-сообщений. Текущее состояние при необходимости
  возвращается через `read_file` (по аналогии с дайджестом чтений). Это основной
  рычаг против бесконтрольного роста assistant-фрагментов.
- **LLM-суммаризация по токеновому порогу (второй эшелон).** Когда даже после
  дайджеста история превышает `context_summary_trigger_tokens` и задан
  суммаризатор, старые незащищённые ходы сворачиваются в накопительный фрагмент
  `summary:rolling`. При отсутствии суммаризатора или ошибке суммаризации
  поведение детерминировано: контекст не меняется.
- **Калибровка оценки токенов по реальному `usage`.** Базовая эвристика бюджета
  считает токены как `bytes/3`, но реальный tokenizer провайдера отличается.
  После каждого обращения к модели harness берёт `usage.prompt_tokens` из ответа
  и сглаживает коэффициент `_token_ratio` (EMA с весом 0.5, ограничение [0.3, 3.0]).
  Все пороги усечения, дропа и переполнения применяются к скорректированной
  оценке — это снижает ложные срабатывания и промахи относительно настоящего
  окна модели. До первого ответа модели ratio равен 1.0 (поведение прежнее).
- **Проактивное усечение по `context_reserve_tokens`.** Дроп истории включается
  не у самого `max_tokens`, а при `max_tokens − reserve`: между порогом дропа и
  жёстким потолком остаётся запас, так что «поздно» не наступает внезапно.
  Жёсткий предел `hard_limit_exceeded` по-прежнему считается от настоящего
  `max_tokens`.
- **Recovery после переполнения (emergency).** Если обычное усечение, LLM-свёртка
  и forced-drop не вписали запрос в бюджет, включается последний эшелон перед
  fatal `RuntimeError`: убираются эвиктируемые рабочие фрагменты (карта проекта,
  напоминание о файлах, скелет свёрнутой истории — всё с `evictability` `normal`
  или `preferred`), затем клипаются project-инструкции и, в крайнем случае,
  системный промпт. Это спасает сессию от падения на пиковом ходе. Только когда
  даже `system + task` не лезут в окно, поднимается честный `RuntimeError` — это
  действительно fatal (бюджет слишком мал для ядра запроса).
- **Списки файлов в свёрнутой истории.** Помимо скелета ходов, фрагмент
  `history:compacted` показывает прочитанные и изменённые в свёрнутом диапазоне
  файлы: модель сохраняет знание, с какими путями работала, даже когда детали хода
  ушли в скелет. Источник — реестр файлового состояния, отфильтрованный по границе
  свёрнутого диапазона.
- **Полный вывод shell-команды во временный файл.** При обрезке длинного
  `stdout`/`stderr` модели отдаётся хвост (там обычно ошибки и итог), а полный
  вывод пишется в `.madharness-mini/tool_outputs/shell-<id>.log` с путём в
  observation — модель может перечитать начало через `read_file`. Старые файлы
  выводов чистятся автоматически (TTL 7 дней при `ensure_dirs`). Поведение
  управляется `context_shell_full_output`.
- **Карта проекта на старте.** При `context_workspace_map` в начале сессии
  добавляется ограниченное по глубине и числу записей дерево каталогов. Карта
  уважает `ignored()` и `protected_paths`, не читает содержимое файлов и строится
  один раз.

## Безопасность

- файловые инструменты проходят через `Policy.safe_path()`;
- protected paths блокируются даже внутри workspace;
- `run_shell` и `run_shell_background` блокируют разрушительные команды
  (`rm -rf`, `sudo`, `curl`, `wget`, `ssh`, `scp`, `chmod 777`, `mkfs`, `dd`)
  и command substitution / brace expansion (обратные кавычки и фигурные скобки
  вне кавычек);
- редирект в файлы запрещён — только `/dev/null` и `/dev/std{out,err}`,
  поэтому shell не может обойти `apply_patch`/`write_file` и `safe_path`;
- по умолчанию команда исполняется через `/bin/sh -c` (`allow_shell_interpreter`):
  операторы `&& ; ||`, `|` и `2>&1` работают; `allow_shell_interpreter=false`
  возвращает прежний режим без интерпретатора, где control-операторы запрещены;
- `run_shell_background` держит процессы в пуле provider'а и гасит их при
  завершении сессии через `ToolRegistry.close()`; число одновременных фоновых
  процессов ограничено `max_background_processes`;
- MCP и hooks запускаются без shell-строки;
- секреты модели не передаются MCP и hooks автоматически;
- payload для hooks обрезается и проходит redaction;
- субагенты получают только разрешённые инструменты.

## Трасса

Каждый `ask` и `run` пишет JSONL-трассу в `.madharness-mini/traces`. В трассе
видны обращения к модели, ответы инструментов, отчёты о контексте, активации
навыков, жизненный цикл MCP, события субагентов и hooks. Это главный учебный
источник для разбора того, что агент реально сделал.

Расширенный `context_report` также становится входом для пассивной диагностики
контекста: отдельный анализатор строит тепловую карту, не меняя поведение
агента. Подробнее об этом инструменте — в документе
[Тепловая карта контекста](context-heatmap.md).
